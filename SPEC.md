## Как работать с этим ТЗ

Claude Code делает проект по этапам из раздела «Этапы», строго по одному этапу за сессию.

1. Выгрузи этот документ в Markdown и положи в корень проекта как `SPEC.md`.
2. Рядом создай `CLAUDE.md` с правилами ниже: Claude Code читает его в начале каждой сессии.
3. Начинай сессию так: «Прочитай SPEC.md. Сделай Этап N. Сначала покажи план, потом делай. В конце скажи, как мне проверить результат».
4. После этапа пройди чек-лист приёмки, сделай коммит в git и только потом бери следующий этап.
5. Этап слишком большой для одной сессии — дроби: «сделай пункты 1–3 Этапа 1».
6. Поменялось решение по ходу — правь `SPEC.md`, а не объясняй в чате: файл переживает сессии, чат нет.

Текст для `CLAUDE.md`:

```markdown
# Правила проекта
- Спецификация: SPEC.md. Делай только тот этап, который я назвал.
- Код и идентификаторы на английском. Тексты для пользователя и комментарии на русском.
- TypeScript в строгом режиме. Секреты только в переменных окружения, пример в .env.example.
- Нейросеть только разбирает фразы. Суммы, итоги, даты и повторы считает код.
- Время храним в UTC (timestamptz), показываем в часовом поясе пользователя.
- Деньги храним в копейках (bigint), никогда не float.
- Схему БД меняем только новой миграцией, старые миграции не трогаем.
- В SPEC.md чего-то нет или есть противоречие: спроси, не придумывай.
- Telegram Bot API, OpenRouter, Supabase: сверяйся с актуальной документацией, а не с памятью.
```

## Суть продукта

Telegram-бот и Mini App, где человек одной фразой записывает трату, доход, встречу или напоминание, а нейросеть сама решает, куда это положить. «Потратил 520 в кафе» становится расходом в категории «Кафе и рестораны», «26 ноября встреча с Вадимом в 7 вечера» становится событием в планере с напоминанием.

Главная фишка — скорость ввода: без форм и выбора категорий. Три способа ввести фразу: текст в бот, голосовое в бот, кнопка действия на iPhone (нажал, продиктовал, записано).

Пользователь — обычный человек, которому лень вести учёт в приложениях с формами. Интерфейс на русском, валюта по умолчанию рубли.

**Входит в первую версию:**

- учёт трат и доходов по категориям;
- события в планере;
- разовые и повторяющиеся напоминания, утренняя сводка;
- статистика трат и ответы на вопросы вроде «сколько я потратил на кафе в октябре»;
- команда для кнопки действия на iPhone;
- Mini App с календарём, списками и графиками;
- подписка Pro за Telegram Stars.

**Не входит:** подключение банков и импорт выписок; общий бюджет на нескольких людей; синхронизация с Google или Apple Calendar; пересчёт валют по курсу; аналог кнопки для Android.

## Стек и архитектура

Всё живёт в Supabase: база Postgres, четыре Edge Functions на TypeScript и планировщик pg_cron. Все входы сходятся в одну функцию `ingest`, поэтому бот, голосовые, iPhone и Mini App ведут себя одинаково.

| Часть | Технология | Зачем |
|---|---|---|
| Бэкенд и БД | Supabase: Postgres, Edge Functions (Deno, TypeScript), pg_cron, pg_net | всё в одном месте, бесплатного тарифа хватит на старт |
| Бот | grammY через webhook | работает внутри Edge Functions |
| Нейросеть | OpenRouter (API в формате OpenAI) за интерфейсом `LlmProvider` | можно сменить на GigaChat или YandexGPT без переписывания |
| Распознавание речи | интерфейс `SttProvider`, провайдер выбираем на Этапе 5 | см. раздел «Голосовые сообщения» |
| Mini App | React, Vite, TypeScript, Telegram WebApp SDK | статический хостинг: Vercel или Cloudflare Pages |
| Проверка данных | zod | схема ответа нейросети и входящих запросов |
| Даты и повторы | date-fns, date-fns-tz, rrule | часовые пояса и повторяющиеся напоминания |
| Тесты | Deno test, Vitest | бэкенд и Mini App |

Edge Functions:

- `telegram-webhook` — принимает апдейты бота: сообщения, голосовые, нажатия кнопок, платежи.
- `shortcut` — эндпоинт для команды iPhone.
- `api` — REST API для Mini App.
- `dispatch-reminders` — pg_cron вызывает её раз в минуту, она рассылает напоминания и утренние сводки.

Поток одной записи:

1. Фраза приходит текстом, голосом (сначала в `SttProvider`, получаем текст) или из команды iPhone.
2. `ingest` вызывает парсер: нейросеть получает фразу, текущие дату и время в поясе пользователя и список его категорий.
3. Ответ проверяется схемой zod, затем код сохраняет записи в БД.
4. Пользователь получает подтверждение в боте с кнопками «Отменить» и «Категория».
5. Ручной ввод формой в Mini App идёт мимо нейросети, сразу в БД.

Архитектура · 4 входа, 4 функции:

```
текст в бот ──┐
голосовое ──► SttProvider ──┤
iPhone (shortcut) ──────────┼──► ingest ──► парсер (LlmProvider) ──► БД ──► подтверждение в бот
поле ввода в Mini App ──────┘
форма в Mini App ─────────────────────────────────────────────────► БД
pg_cron (раз в минуту) ──► dispatch-reminders ──► БД ──► сообщения в бот
```

Бот, голосовые, iPhone и поле ввода в Mini App идут через `ingest`; ручной ввод формой пишет в базу напрямую, а `dispatch-reminders` раз в минуту забирает из базы то, что пора отправить.

### Структура репозитория

Один репозиторий: бэкенд в `supabase/`, Mini App в `miniapp/`, служебные скрипты в `scripts/`.

```
/
├─ SPEC.md, CLAUDE.md, README.md, .env.example
├─ supabase/
│  ├─ config.toml
│  ├─ migrations/            SQL-миграции
│  ├─ seed.sql               категории по умолчанию
│  └─ functions/
│     ├─ _shared/
│     │  ├─ db.ts            клиент Supabase (service role)
│     │  ├─ ingest.ts        фраза → записи → подтверждение
│     │  ├─ parser/          промпт, схема zod, вызов нейросети
│     │  ├─ llm/             LlmProvider + openrouter.ts
│     │  ├─ stt/             SttProvider
│     │  ├─ telegram.ts      отправка сообщений, клавиатуры
│     │  ├─ time.ts          часовые пояса, форматирование дат
│     │  ├─ money.ts         копейки ↔ рубли, форматирование сумм
│     │  └─ auth.ts          initData, личные токены, секрет вебхука
│     ├─ telegram-webhook/
│     ├─ shortcut/
│     ├─ api/
│     └─ dispatch-reminders/
├─ miniapp/                  React + Vite
└─ scripts/
   ├─ set-webhook.ts         регистрация вебхука и списка команд
```

У всех четырёх функций выключить стандартную проверку JWT (`verify_jwt = false` в `config.toml`). Вместо неё каждая проверяет своё: `telegram-webhook` — секрет вебхука, `shortcut` — личный токен, `api` — initData, `dispatch-reminders` — `CRON_SECRET`.

### Среда разработки

**Решено:** разработка сразу на облачном проекте Supabase (`vsoyzznzbwaedomvjcfe`), без Docker и без локального Supabase. Причины: Docker на машине нет, а вебхуку Telegram всё равно нужен публичный HTTPS-адрес, который у облачных функций есть сразу.

- Supabase CLI привязан к облачному проекту: `supabase link --project-ref vsoyzznzbwaedomvjcfe`. CLI авторизуется через `SUPABASE_ACCESS_TOKEN` и `SUPABASE_DB_PASSWORD` из `.env`.
- Миграции применяются к облачной базе: `supabase db push --db-url "$SUPABASE_DB_URL"`. Прямой хост базы `db.vsoyzznzbwaedomvjcfe.supabase.co` доступен только по IPv6, с машины разработчика соединение рвётся. Поэтому CLI ходит в базу через pooler в session mode: `aws-0-eu-west-1.pooler.supabase.com:5432`, пользователь `postgres.vsoyzznzbwaedomvjcfe`. Готовая строка лежит в `SUPABASE_DB_URL` в `.env`.
- Регион проекта — `eu-west-1` (Ирландия), ближе к серверам Telegram и пользователям в России.
- Функции выкладываются без Docker: `supabase functions deploy <name> --use-api` (сборка на стороне Supabase).
- Секреты функций: `supabase secrets set --env-file <файл>`. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` в облачных функциях доступны автоматически (сверить с документацией), остальные загружаются этой командой.
- Юнит-тесты (`deno test`) идут локально и не ходят ни в базу, ни в нейросеть. Сквозная проверка — на облачном проекте через настоящего бота.
- Облачная база одна, для разработки и для себя. Отдельный тестовый проект — когда появятся другие пользователи.

## Модель данных

Восемь таблиц. Ниже черновик схемы: Claude Code оформляет его миграциями и может уточнять типы, но не смысл полей.

```sql
-- Пользователи
create table users (
  id uuid primary key default gen_random_uuid(),
  telegram_id bigint unique not null,
  first_name text, username text,
  timezone text not null default 'Europe/Moscow',  -- IANA
  currency text not null default 'RUB',
  digest_enabled boolean not null default true,
  digest_time time not null default '08:00',       -- локальное время пользователя
  plan text not null default 'free',               -- free | pro
  pro_until timestamptz,
  shortcut_token_hash text unique,                 -- sha256 личного токена для iPhone
  is_blocked boolean not null default false,       -- пользователь заблокировал бота
  onboarded_at timestamptz,
  created_at timestamptz not null default now()
);

-- Категории: общие (user_id is null) и свои
create table categories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users on delete cascade,
  kind text not null check (kind in ('expense','income')),
  name text not null,
  emoji text,
  sort int not null default 0,
  archived boolean not null default false
);

-- Один ввод пользователя = одна строка (для отмены, отладки и учёта расходов на нейросеть)
create table entries (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users on delete cascade,
  source text not null,          -- bot_text | bot_voice | shortcut | miniapp
  raw_text text not null,
  parsed jsonb,                  -- ответ парсера после проверки
  status text not null,          -- saved | needs_clarification | failed | undone
  bot_message_id bigint,         -- сообщение-подтверждение в чате
  llm_model text, llm_tokens_in int, llm_tokens_out int, llm_ms int,
  created_at timestamptz not null default now()
);

-- Деньги
create table transactions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users on delete cascade,
  entry_id uuid references entries on delete set null,
  kind text not null check (kind in ('expense','income')),
  amount_minor bigint not null check (amount_minor > 0),  -- копейки
  currency text not null default 'RUB',
  category_id uuid references categories,
  note text,
  occurred_at timestamptz not null,
  deleted_at timestamptz,
  created_at timestamptz not null default now()
);

-- Планер
create table events (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users on delete cascade,
  entry_id uuid references entries on delete set null,
  title text not null,
  note text,
  starts_at timestamptz not null,
  ends_at timestamptz,
  all_day boolean not null default false,
  deleted_at timestamptz,
  created_at timestamptz not null default now()
);

-- Напоминания: к событию или сами по себе, разовые или повторяющиеся
create table reminders (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users on delete cascade,
  entry_id uuid references entries on delete set null,
  event_id uuid references events on delete cascade,
  text text not null,
  next_fire_at timestamptz,      -- null = больше не сработает
  rrule text,                    -- RFC 5545, например FREQ=MONTHLY;BYMONTHDAY=5,10
  dtstart_local timestamp,       -- отсчёт повтора в поясе пользователя
  last_sent_at timestamptz,
  active boolean not null default true,
  created_at timestamptz not null default now()
);

-- Защита от повторной обработки апдейтов Telegram
create table processed_updates (
  update_id bigint primary key,
  created_at timestamptz not null default now()
);

-- Платежи Stars (Этап 6)
create table payments (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users,
  telegram_payment_charge_id text unique not null,
  amount_stars int not null,
  is_recurring boolean,
  period_end timestamptz,
  raw jsonb not null,
  created_at timestamptz not null default now()
);
```

Правила:

- RLS включён на всех таблицах, политик для анонимного доступа нет. Весь доступ идёт через Edge Functions с service role; Mini App ходит только в `api`.
- Индексы: `transactions (user_id, occurred_at desc)`, `events (user_id, starts_at)`, `reminders (next_fire_at) where active`.
- Удаление мягкое через `deleted_at`. Исключение — `/delete_me`: там удаляется всё.
- В `entries` исходная фраза хранится 90 дней, потом `raw_text` затирается ежедневной задачей.

Категории по умолчанию (в `seed.sql`, `user_id is null`):

- **Расходы:** Продукты, Кафе и рестораны, Транспорт, Такси, Дом и ЖКХ, Связь и интернет, Здоровье, Красота, Одежда и обувь, Развлечения, Подписки, Подарки, Образование, Животные, Другое.
- **Доходы:** Зарплата, Подработка, Переводы, Кэшбэк, Другое.

## Разбор фраз нейросетью

Нейросеть только превращает фразу в JSON. Сохранение, суммы, итоги и следующее срабатывание повтора делает код.

Что получает модель:

- текущие дату, время и день недели в поясе пользователя, например `2026-10-26 15:51, понедельник, Europe/Samara`;
- названия категорий пользователя и валюту по умолчанию;
- саму фразу, обрезанную до 500 символов.

Имя, username и telegram_id в нейросеть не уходят.

Что возвращает модель — строго по JSON-схеме (structured output), массив `items`, в одной фразе может быть несколько записей:

```json
{
  "items": [
    { "type": "expense", "amount": 520, "currency": "RUB", "category": "Кафе и рестораны", "note": "кафе", "occurred_at": "2026-10-26T15:51:00+04:00" },
    { "type": "income", "amount": 85000, "currency": "RUB", "category": "Зарплата", "note": null, "occurred_at": "2026-10-26T15:51:00+04:00" },
    { "type": "event", "title": "Встреча с Вадимом", "starts_at": "2026-11-26T19:00:00+04:00", "ends_at": null, "all_day": false, "remind_before_min": [60] },
    { "type": "reminder", "text": "Оплатить кредит", "first_at": "2026-11-05T10:00:00+04:00", "rrule": "FREQ=MONTHLY;BYMONTHDAY=5,10;BYHOUR=10;BYMINUTE=0" },
    { "type": "query", "metric": "expense_sum", "period_from": "2026-10-01", "period_to": "2026-10-31", "category": "Кафе и рестораны" },
    { "type": "clarify", "question": "Сколько стоили кроссовки?" },
    { "type": "other" }
  ]
}
```

`metric` у запроса: `expense_sum`, `income_sum`, `balance`, `events_list`. Ответ на запрос считает SQL, не модель.

Правила для промпта:

1. Несколько записей в одной фразе: «такси 340 и обед 450» — две траты.
2. Суммы: «5к» = 5000, «2,3к» = 2300, «полторы тысячи» = 1500, «косарь» = 1000, «пятихатка» = 500; «520р», «520 руб», «520 ₽» — одно и то же; копейки допустимы: «99,90».
3. Тип: «потратил, заплатил, купил, отдал» — расход; «получил, пришла зарплата, вернули, кэшбэк» — доход. Сумма с предметом без глагола («кофе 250») — расход.
4. Даты считаются от текущего момента пользователя: «вчера», «в пятницу» (для планов ближайшая будущая, для трат прошедшая), «через 2 часа», «26 ноября» (дата этого года уже прошла — значит следующий год). Трата без даты — сейчас.
5. Время без «утра» или «вечера» — ближайшее будущее подходящее время. Подтверждение всегда показывает итоговые дату и время, чтобы ошибку было видно.
6. Событие без времени — `all_day: true`, о нём напомнит утренняя сводка.
7. Событие со временем получает напоминание за 60 минут, если человек не сказал иначе («напомни за день»).
8. «Напомни …» без встречи — `reminder`. «Каждый месяц 5 и 10 числа» — `rrule`. Время не указано — 10:00.
9. Категория только из переданного списка; ничего не подходит — «Другое». Новые категории модель не создаёт.
10. Нет суммы, непонятна дата или смысл — `clarify` с одним коротким вопросом, ничего не сохраняется.
11. Вопросы «сколько я потратил…» — `query`, модель ничего не считает.
12. Не про деньги и не про планы («привет») — `other`, бот отвечает подсказкой с примерами.

Проверка ответа:

- Ответ проверяется схемой zod. Не прошёл — один повтор с текстом ошибки; снова не прошёл — запасная модель; снова — «Не понял, перефразируй» и `entries.status = failed`.
- Проверки в коде: сумма больше 0 и меньше 100 000 000 ₽; трата не позже чем через сутки от текущего момента; встреча не в прошлом (иначе `clarify`).
- Температура 0, таймаут запроса 15 секунд.

**Эталонные фразы.** Момент проверки: 2026-10-26 15:51, понедельник, Europe/Samara. Это начало набора: `scripts/parser-golden.ts` гоняет 30 и больше фраз через настоящую модель и печатает точность. Запускать вручную перед сменой промпта или модели.

## Бот

Любой текст, который не команда, идёт в `ingest`; на каждую запись бот отвечает подтверждением, которое можно отменить одной кнопкой.

Онбординг по `/start`:

1. Приветствие в 2–3 строки с примером фразы.
2. Выбор часового пояса кнопками: Калининград, Москва, Самара, Екатеринбург, Омск, Новосибирск, Красноярск, Иркутск, Якутск, Владивосток, «Другой» (список в Mini App).
3. Подсказка: пиши как другу — «кофе 250», «завтра в 15 созвон», «напомни 5 числа оплатить интернет». Предложение настроить кнопку на iPhone через `/shortcut`.

Обработка сообщения:

1. Отправить статус «печатает».
2. Проверить лимит тарифа (раздел «Подписка»).
3. Вызвать `ingest`.
4. Ответить подтверждением, строка на запись, например: «Записал: расход 520 ₽ · Кафе и рестораны · сегодня 15:51». Эмодзи в сообщениях бота — на усмотрение, коротко.
5. Кнопки под подтверждением: «Отменить»; для трат — «Категория» (выбор из списка); для событий — «Изменить» (открывает запись в Mini App).
6. «Отменить» помечает удалёнными все записи этой фразы и меняет сообщение на «Отменено». Работает 48 часов.
7. `clarify`: бот задаёт вопрос; следующий ответ склеивается с исходной фразой и разбирается заново. Ожидание уточнения живёт 10 минут.
8. `query`: код считает и отвечает, например «В октябре на кафе: 7 430 ₽, 12 трат».

Изменённые пользователем сообщения в первой версии игнорируются.

## Напоминания и планировщик

pg_cron раз в минуту вызывает `dispatch-reminders` через pg_net с заголовком `CRON_SECRET`; функция рассылает всё, чему пора сработать.

1. Атомарно забрать до 200 напоминаний с `active and next_fire_at <= now()` (`update … returning` с `for update skip locked`), чтобы два запуска не отправили одно и то же.
2. Каждому отправить сообщение с кнопками «Готово», «Через час», «Завтра».
3. Записать `last_sent_at`. Есть `rrule` — посчитать следующее срабатывание в поясе пользователя и записать в `next_fire_at`. Нет — `active = false`.
4. Сработало позже чем на час (функция лежала) — отправить с пометкой «напоминание запоздало».

Напоминание к событию:

- создаётся вместе с событием: `next_fire_at = starts_at − remind_before_min`;
- перенос события пересчитывает напоминание, удаление события выключает его.

Утренняя сводка:

- в `digest_time` по поясу пользователя, если `digest_enabled`;
- состав: события на сегодня (включая события на весь день), напоминания на сегодня, траты за вчера одной строкой;
- пустой день — сводку не слать.

Ограничения Telegram:

- отправлять пачками, не больше 25 сообщений в секунду на весь бот;
- ответ 429 — подождать `retry_after` и повторить;
- ответ 403 (бот заблокирован) — `users.is_blocked = true` и выключить все его напоминания.

## Команда для iPhone (кнопка действия)

Быстрая команда диктует фразу на самом айфоне и отправляет готовый текст на `shortcut`, поэтому распознавание речи для этого входа не нужно.

Эндпоинт:

- `POST /functions/v1/shortcut`, заголовок `Authorization: Bearer <личный токен>`, тело `{"text": "..."}`.
- Ответ `200 {"message": "Записал: расход 520 ₽ · Кафе и рестораны"}` — одна короткая строка, команда показывает её уведомлением. То же подтверждение с кнопкой «Отменить» приходит в бот.
- `401` — неверный токен; `429` — больше 20 запросов в минуту; `402` — кончился бесплатный лимит. В `message` всегда понятный человеку текст, что делать.

Личный токен:

- `/shortcut` генерирует случайный токен (32 байта, base64url), показывает его один раз, в БД хранит только sha256.
- Повторный `/shortcut` выпускает новый токен, старый сразу перестаёт работать.

Шаги команды. Собираешь один раз вручную, потом раздаёшь ссылкой iCloud:

1. «Диктовать текст» — язык русский, остановка после паузы.
2. «Получить содержимое URL» — метод POST, заголовок `Authorization` = `Bearer` + токен, тело JSON с полем `text` = продиктованный текст.
3. «Получить значение из словаря» — ключ `message`.
4. «Показать уведомление» с этим значением.

Токен задаётся вопросом при импорте: при установке по ссылке айфон сам попросит вставить токен.

Что присылает `/shortcut`: ссылку на команду, токен и подсказку «Настройки → Кнопка действия → Быстрая команда → выбрать нашу». На айфонах без кнопки действия команду запускают голосом через Siri по её названию или касанием задней панели.

В `README.md` Claude Code описывает эти шаги с точными названиями действий, чтобы команду можно было собрать без догадок.

## Mini App

Mini App — витрина и ручной ввод: пять экранов, вход без логина через initData от Telegram.

Авторизация:

- каждый запрос к `api` несёт заголовок `Authorization: tma <initData>`;
- `api` проверяет подпись initData по алгоритму из документации Telegram (HMAC-SHA256, ключ выводится из токена бота), отклоняет данные старше 24 часов и берёт `telegram_id` из поля `user`;
- алгоритм сверить с актуальной документацией Telegram Mini Apps.

Экраны:

1. **Сегодня** — поле ввода фразы сверху (тот же `ingest`), события и напоминания на сегодня, траты за день, расходы месяца против прошлого месяца на ту же дату.
2. **Финансы** — операции по дням, фильтры по периоду, категории и типу, диаграмма по категориям за месяц, добавление и правка формой, удаление.
3. **Планер** — календарь на месяц и неделю с отметками событий, список на выбранный день, создание и правка формой.
4. **Напоминания** — активные и повторяющиеся, правило повтора словами («каждый месяц 5 и 10 числа в 10:00»), выключить или удалить.
5. **Настройки** — часовой пояс, утренняя сводка, категории (переименовать, добавить, скрыть), команда для iPhone, экспорт CSV, тариф, удаление данных.

Внешний вид:

- цвета из `themeParams` Telegram, светлая и тёмная тема без отдельной вёрстки;
- «Назад» через `BackButton`, главное действие экрана через нижнюю кнопку Telegram;
- сначала под телефон, корректно от ширины 320 px;
- суммы «7 430 ₽», даты по-русски, неделя с понедельника.

API (REST, JSON):

| Метод и путь | Что делает |
|---|---|
| `GET /me`, `PATCH /me` | профиль и настройки |
| `POST /ingest` | фраза через нейросеть, как в боте |
| `GET /transactions?from&to&category&kind` | список операций |
| `POST /transactions`, `PATCH /transactions/:id`, `DELETE /transactions/:id` | ручной ввод, правка, удаление |
| `GET /stats?from&to` | суммы по категориям, считает SQL |
| `GET /events?from&to`, `POST`, `PATCH /:id`, `DELETE /:id` | планер |
| `GET /reminders`, `PATCH /:id`, `DELETE /:id` | напоминания |
| `GET /categories`, `POST`, `PATCH /:id` | категории |
| `GET /export.csv` | выгрузка операций |
| `POST /shortcut-token` | перевыпуск токена для iPhone |
| `POST /pro/invoice` | ссылка на счёт в Stars (Этап 6) |

## Голосовые сообщения

Голосовое в бот превращается в текст и идёт в тот же `ingest` с `source = bot_voice`; провайдер распознавания выбирается перед Этапом 5.

- Бот принимает voice до 60 секунд; длиннее — вежливо просит сказать короче.
- Файл скачивается через `getFile` и уходит в `SttProvider.transcribe(audio, "ru")`.
- В подтверждении показывается распознанный текст цитатой, чтобы ошибку распознавания было видно сразу.
- Голосовые считаются в тот же лимит записей, что и текст.

Требования к провайдеру: русский язык; принимает OGG/Opus без перекодирования (в Edge Functions нет ffmpeg); оплата доступна из России.

Кандидаты на проверку: Yandex SpeechKit, модели с аудиовходом через OpenRouter, сервисы с API в формате Whisper. Перед реализацией Claude Code сверяет по документации поддержку формата, лимиты длины и цену и предлагает выбор.

## Подписка и оплата

Pro продаётся только за Telegram Stars: цифровые товары и услуги в ботах и Mini App Telegram разрешает оплачивать исключительно в Stars ([объявление Telegram](https://telegram.space/s/tgsucks?after=3723)). Внешние платёжки не используем.

Тарифы — черновик, цифры решаешь ты:

| Возможность | Free | Pro |
|---|---|---|
| Записи через нейросеть (текст, голос, iPhone) | `FREE_AI_ENTRIES_PER_MONTH` в месяц | без лимита, технический потолок 1 000 в месяц |
| Ручной ввод в Mini App | без лимита | без лимита |
| Разовые напоминания | да | да |
| Повторяющиеся напоминания | до 3 | без лимита |
| Статистика | текущий месяц | любой период |
| Экспорт CSV | нет | да |

Оплата:

1. `/pro` или кнопка в Mini App вызывает `createInvoiceLink`: `currency = "XTR"`, одна позиция в `prices`, `subscription_period = 2592000`. Сейчас для подписок Telegram принимает только это значение, 30 дней ([пример в коде библиотеки](https://docs.rs/crate/teloxide-core/latest/source/src/payloads/create_invoice_link.rs)); цена не больше 10 000 Stars.
2. В Mini App счёт открывается через `openInvoice`, в боте ссылка приходит кнопкой.
3. `pre_checkout_query` — сразу ответить `answerPreCheckoutQuery` с `ok: true`, если пользователь существует.
4. `successful_payment` — запись в `payments`, `plan = pro`, `pro_until` = дата окончания подписки из платежа.
5. Продления приходят новыми `successful_payment`. Тариф считается по дате: после `pro_until` без продления пользователь снова Free, отдельный флаг не нужен.
6. Возврат — `refundStarPayment` по `telegram_payment_charge_id`, только через `/admin`.
7. Команда `/paysupport` для вопросов по оплате.

Поля платежа, отмену подписки и условия Telegram для продавцов Claude Code сверяет с актуальной документацией Bot API перед реализацией.

На лимите бесплатных записей бот не молчит: объясняет, что лимит кончился, предлагает Pro и напоминает, что ручной ввод в Mini App работает без лимита.

## Безопасность, приватность, расходы, тесты

Эти требования действуют на всех этапах, а не отдельным этапом.

### Безопасность

- Вебхук регистрируется с `secret_token`; апдейт без верного `X-Telegram-Bot-Api-Secret-Token` получает 401.
- `update_id` пишется в `processed_updates`; повтор получает 200 без обработки. Записи старше 7 дней чистятся.
- Секреты только в переменных окружения Supabase. В логи не попадают токены, initData, ключи и тексты фраз.
- RLS включён везде, у анонимного ключа нет доступа к таблицам.
- Не больше 20 вводов через нейросеть в минуту на пользователя.

### Приватность

- Политика конфиденциальности обязательна для ботов и Mini App ([новость Telegram](https://t.me/s/Botnews/101)): ссылка в `/settings`, в Mini App и в описании бота.
- `/delete_me` удаляет все строки пользователя во всех таблицах.
- В нейросеть уходят только фраза, дата и пояс, названия категорий.
- По закону данные граждан РФ положено хранить на серверах в России, а Supabase за рубежом. Для теста это осознанный риск; до платного запуска проверить у юриста. Поэтому только стандартный Postgres и свои интерфейсы для нейросети и распознавания речи: переезд в российское облако должен быть заменой подключений, а не переписыванием.

### Расходы на нейросеть

- Каждый вызов пишет в `entries` модель, токены и время ответа; `/admin` показывает расход за сутки и месяц.
- Фраза обрезается до 500 символов, промпт короткий, категории передаются только названиями.
- Превышен `LLM_DAILY_CAP` — бот отвечает, что временно принимает только ручной ввод в Mini App, и пишет админу.

### Надёжность

- Таймаут запроса к нейросети 15 секунд, затем запасная модель.
- Ошибки пишутся в лог и приходят админу в Telegram, не чаще раза в 10 минут на один тип ошибки.

### Тесты

- Юнит-тесты без нейросети: суммы (разбор и форматирование), часовые пояса, следующее срабатывание rrule (31-е число, февраль, переход декабрь → январь), проверка initData, проверка секрета вебхука, схема ответа парсера.
- Эталонные фразы парсера — отдельный скрипт с настоящей моделью, запускается вручную.
- Перед сдачей этапа: `deno lint`, `deno check`, все тесты зелёные.
